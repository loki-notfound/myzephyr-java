13. Known limitations

These are the limits a wallet app runs into with 2.3.0-sec.2-java.4. Most come from the Zephyr core (zephyr-cpp and wallet2), which zephyr-java builds unchanged. The backports change the core only for security fixes, so functional gaps stay until the core itself changes. Each row says what happens, its status, and where the details are. The rest of the guide explains each one where its topic is.

Status words:

  • core: behaviour of the Zephyr core;
  • open: not fixed;
  • observed: the run that showed it, with its date;
  • not tested: nobody ran it against Zephyr.

What was tested#

  • On mainnet with real funds, on the desktop: create, open, sync, balances per asset, transfers, a ZPH → ZRS conversion and sweeps. Five transactions were verified on the node. Conversions other than ZPH → ZRS were not run (What was tested).
  • On the Android emulator: see below.
  • On Linux x86_64 on 2026-11-17, with a developer build of the 2.3.0-sec.2-java.4 sources: listener exceptions, closing during a sync and reads from several threads. Also the messages of createTxs, the native log, a view-only wallet, moveTo, the heights and the amount helpers. The closing runs, the listener exceptions under background syncing, the wrong password and the native log's content were repeated that day with the released JAR.
  • The coexistence with monero-java in one JVM (Both libraries in one program).

Where it has run. The x86_64 library ran on the Android emulator as a release check. It ran on API 24 and on API 35 with 16 KB pages, in debug builds (so under ART's CheckJNI). There:

  • the native library loads, and an offline wallet works;
  • a wallet restored from its mnemonic syncs against a mainnet node and opens again from its bytes;
  • ZephyrDaemonRpc reads the node (on API 24 with desugaring);
  • https:// to a mainnet node with a publicly signed certificate works without setup (the shipped root certificates), on API 24 and on API 35 with 16 KB pages;
  • with the system store alone it works on API 35 and fails on API 24, which lacks ISRG Root X1.

The arm64-v8a and armeabi-v7a libraries are built and checked the same way (exports, page alignment, packaging). They had not run on hardware by release 2.3.0-sec.2-java.4 (2026-11-10).

What was not tested#

  • the conversions other than ZPH → ZRS on mainnet;
  • the ARM libraries for Android on hardware;
  • the Linux arm64 library, which is built and checked but has not been run;
  • any of the observations of 2026-11-17 on Android, and configureNativeLogging on Android;
  • the areas inherited from monero-java listed in What zephyr-java does and does not do;
  • a node that refuses a relayed transaction, and the message for funds that are not unlocked;
  • a large history, and a first sync over the internet from an old restore height.
