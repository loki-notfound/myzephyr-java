zephyr-java user guide

This guide explains how to use zephyr-java in an application. It covers desktop and server JVMs with the JAR, and Android apps with the AAR. It assumes you know Java; it does not assume you know monero-java. The README has the coordinates and a complete quick-start program. The API reference is the Javadoc of the current release.

Not affiliated with ZephyrProtocol. An independent project.

This guide describes version 2.3.0-sec.2-java.4.

Conventions#

  • Fragments. A short Java block that uses wallet means an open ZephyrWalletFull; the block does not show how it was opened.
  • Compiled examples. A block whose label is "Java, compiled" on the site (info string java examples/<Class>.java in the Markdown) is copied from that class in src/test/java/examples/. The class is compiled with every mvn test, and the test TestExamples fails when the block and the class differ. Other blocks are fragments and are not compiled.
  • Placeholders. Values you supply are written in angle brackets, such as <version>, and explained below the block. Example hosts end in .example.invalid.
  • Amounts. Every amount in the API is a BigInteger in atomic units, 10^12 per coin for every asset. Prose names amounts in coins with the asset's ticker after the number.
  • Dates. Dates are absolute and in UTC. A statement about a release names that release.

Where the statements come from#

Statements about the Zephyr core come from the pinned sources and from test runs against mainnet. Those runs took place from 2026-11-06 to 2026-11-10, during the work on the releases up to 2.3.0-sec.2-java.4. Each such statement names its date where it matters.

Statements marked "observed on 2026-11-17" come from runs against a mainnet node on Linux x86_64 (Debian 13, OpenJDK 21). Most used a developer build of the 2.3.0-sec.2-java.4 sources. Those marked "with the released JAR" used zephyr-java-2.3.0-sec.2-java.4.jar and its own native library. None of those runs was made on Android. One run is an observation, not a guarantee: a run that found no failure proves no safety.

Statements marked "read in the code" come from the source of this library or of the pinned core, not from a run. Where a fact is not known, the guide says so.
